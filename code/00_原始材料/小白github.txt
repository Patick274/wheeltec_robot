小白第一次创建 GitHub 仓库与代码上传/更新教程（含注释）
========================================================

本教程按“文件夹”分节：
  文件夹一：小白第一次创建 GitHub 仓库（配置好注释）
  文件夹二：第一次代码上传以及推送方式（A/B/C/D 方式）
           末尾补充：创建分支、选择分支、推送分支
  文件夹三：在另一台电脑的下拉与上传方式（A/B/C/D 方式）
  文件夹四：常见的问题（1~6）


========================================================
文件夹一：小白第一次创建 GitHub 仓库（配置好注释）
========================================================

1.1 注册 GitHub 账号
  - 打开 https://github.com，点 Sign up
  - 记好用户名，后面 remote 地址会用到
  - 用户名大小写、拼写必须完全一致

1.2 安装 Git
  Windows：到 https://git-scm.com 下载安装，一路下一步
  Mac：
    brew install git
    # 用 Homebrew 安装 Git
  Linux：
    sudo apt install git
    # Debian/Ubuntu 系安装 Git

  验证：
    git --version
    # 能输出版本号即安装成功

1.3 配置 Git 身份（首次使用做一次）
    git config --global user.name "你的名字"
    # 设置提交记录里显示的名字

    git config --global user.email "你的邮箱"
    # 设置提交记录里显示的邮箱，建议和 GitHub 账号一致

  查看配置：
    git config --global --list
    # 列出全局配置，确认 name 和 email 正确

1.4 在 GitHub 上创建“空仓库”
  - 登录 GitHub → 右上角 + → New repository
  - Repository name 填仓库名，例如 PHM
  - README / .gitignore / license 三个都不要勾
    # 勾了会在远程生成初始提交，首次 push 容易报 fetch first
  - 点 Create repository
  - 复制仓库地址，两种格式：
      HTTPS：https://github.com/你的用户名/仓库名.git
      SSH：  git@github.com:你的用户名/仓库名.git

1.5 判断当前目录是不是 Git 仓库
    git rev-parse --show-toplevel
    # 输出仓库根目录；报 not a git repository 说明当前目录及父目录都没有 .git

    git status
    # 能列出当前分支和文件状态，说明在仓库内

  如果不在仓库内：
    cd 项目根目录
    git init
    # 在当前目录初始化 Git 仓库，生成 .git 文件夹
    # 不要在子目录随手 git init，避免嵌套仓库

1.6 确定本地分支叫 master 还是 main
    git branch
    # 星号 * 所在行是当前分支，常见 master 或 main

  本地和远程分支名不一致时，两种处理：
    方式 A：本地改名成 main，和 GitHub 默认一致（推荐）
        git branch -M main
        # -M 强制重命名当前分支为 main

    方式 B：保持 master 直接推
        git push -u origin master
        # origin 是远程名，master 是分支名


========================================================
文件夹二：第一次代码上传以及推送方式
========================================================

说明：
  A 网页上传：最简单，不用装工具
  B GitHub Desktop：图形界面
  C 命令行 + HTTPS + PAT：会一点命令行，不想配 SSH 密钥
  D 命令行 + SSH：长期开发推荐，配一次免密推送

--------------------------------------------------------
A 方式：网页直接上传
--------------------------------------------------------
适用：文件少（<100 个）、单个文件 <25MB，不要求保留提交历史。

步骤：
  1. 打开刚创建的空仓库页面
  2. 点 Add file → Upload files
  3. 把项目文件夹拖进网页
  4. 下方写提交说明，例如 first commit
  5. 点绿色 Commit changes

缺点：
  - 不能保留本地多次提交历史
  - 没有真正的本地“下拉更新”，后续建议改用命令行或 Desktop

--------------------------------------------------------
B 方式：GitHub Desktop（图形界面）
--------------------------------------------------------
适用：不想碰命令行。

步骤：
  1. 到 https://desktop.github.com 下载安装
  2. 打开后 Sign in to GitHub.com
  3. File → Add local repository → 选择项目文件夹
  4. 如果没有仓库，点 create a repository，名字填仓库名
  5. 左下角写提交说明 → Commit to main
  6. 右上角 Publish repository
     # 取消勾选 Keep this code private 就是公开仓库

--------------------------------------------------------
C 方式：命令行 + HTTPS + PAT
--------------------------------------------------------
前提：GitHub 已禁用账号密码推送，必须用 PAT（个人访问令牌）。

生成 PAT：
  1. GitHub → 头像 → Settings
  2. Developer settings → Personal access tokens → Tokens (classic)
  3. Generate new token (classic)
  4. 权限勾 repo
  5. 生成后立刻复制 ghp_ 开头的令牌

首次上传命令：
    cd 你的项目文件夹
    # 进入项目根目录

    git init
    # 初始化本地仓库

    git add .
    # 把所有文件加入暂存区
    # 执行前先 git status，确认没有 __pycache__、.venv、大文件

    git commit -m "first commit"
    # 提交到本地仓库，-m 后是提交说明

    git branch -M main
    # 当前分支重命名为 main；保留 master 可跳过

    git remote add origin https://github.com/你的用户名/仓库名.git
    # 添加远程仓库，名字 origin，地址 HTTPS

    git remote -v
    # 确认远程地址已添加

    git push -u origin main
    # 推到远程 main，-u 建立上游关联
    # 本地是 master 就写 git push -u origin master

  推送时输入：
    用户名：GitHub 用户名
    密码：粘贴 PAT 令牌，不是账号密码

  可选：记住凭据
    git config --global credential.helper store
    # 下次输入一次后保存，不再反复询问

--------------------------------------------------------
D 方式：命令行 + SSH 密钥（推荐）
--------------------------------------------------------
注意：SSH 密钥和远程地址是两件事。
  密钥解决“有没有权限”，remote 解决“推到哪个仓库”。

生成密钥：
    ssh-keygen -t ed25519 -C "你的邮箱"
    # -t 指定密钥类型，-C 是备注
    # 一路回车，使用默认路径

查看公钥：
    cat ~/.ssh/id_ed25519.pub
    # 复制 ssh-ed25519 开头的整串公钥

添加到 GitHub：
  Settings → SSH and GPG keys → New SSH key → 粘贴公钥

测试：
    ssh -T git@github.com
    # 看到 Hi 你的用户名! You've successfully authenticated 说明密钥可用

首次上传命令：
    cd 你的项目文件夹
    # 进入项目根目录

    git init
    # 初始化本地仓库

    git add .
    # 加入暂存区

    git commit -m "first commit"
    # 提交到本地仓库

    git branch -M main
    # 重命名为 main；保留 master 可跳过

    git remote add origin git@github.com:你的用户名/仓库名.git
    # 添加远程地址，SSH 格式

    git remote -v
    # 确认 origin 的 fetch 和 push 两行地址

    git push -u origin main
    # 推到远程并建立上游关联
    # 本地是 master 就写 git push -u origin master

--------------------------------------------------------
补充：创建分支、选择分支、推送分支
（放在本文件夹末尾）
--------------------------------------------------------
查看分支：
    git branch
    # 星号 * 是当前分支

创建并切换到新分支：
    git switch -c 你的分支名
    # -c 表示创建并切换，新分支基于当前分支最新提交
    # 旧版 Git 也可用：git checkout -b 你的分支名

示例：
    git switch -c feature-lift-control
    # 创建并切换到 feature-lift-control 分支

选择/切换已有分支：
    git switch 你的分支名
    # 切换到已有分支
    # 旧版 Git：git checkout 你的分支名

查看所有分支（含远程）：
    git branch -a
    # 列出本地和远程分支

在新分支上修改并提交：
    git add .
    # 添加修改

    git commit -m "说明这次改了什么"
    # 提交到当前分支

推送新分支到远程：
    git push -u origin 你的分支名
    # 第一次推新分支要带 -u，建立上游关联
    # 之后直接 git push 即可

示例：
    git push -u origin feature-lift-control

把新分支合并回 main（可选）：
    git switch main
    # 切回 main

    git pull origin main
    # 先拉取远程 main 最新代码

    git merge feature-lift-control
    # 把功能分支合并进 main

    git push origin main
    # 推送合并后的 main

删除本地分支（可选，确认已合并后）：
    git branch -d 你的分支名
    # -d 删除已合并分支；未合并需 -D 强制删除

删除远程分支（可选）：
    git push origin --delete 你的分支名
    # 删除远程分支


========================================================
文件夹三：在另一台电脑的下拉与上传方式
========================================================
场景：A 电脑已上传代码，B 电脑 clone 后修改，再更新回仓库。

A 方式：网页下载 ZIP（不推荐）
--------------------------------------------------------
  1. 仓库页面 → Code → Download ZIP
  2. 解压后修改
  3. 网页 Upload files 覆盖上传
  缺点：没有提交历史，容易覆盖别人修改，不推荐长期使用。

B 方式：GitHub Desktop
--------------------------------------------------------
  1. 打开 GitHub Desktop，登录账号
  2. File → Clone repository → 选择远程仓库
  3. 选择本地保存路径 → Clone
  4. 修改代码
  5. 左下角写提交说明 → Commit to main
  6. 点 Push origin

C 方式：命令行 + HTTPS
--------------------------------------------------------
首次克隆：
    git clone https://github.com/你的用户名/仓库名.git
    # 把远程仓库完整复制到本地，自动配置 origin

    cd 仓库名
    # 进入仓库目录

日常更新：
    git pull origin main
    # 拉取远程 main 最新提交
    # 本地是 master 就写 git pull origin master

    git add .
    # 添加本地修改

    git commit -m "说明"
    # 提交到本地仓库

    git push
    # 推送到远程；clone 时已建立上游关联，可直接 push

D 方式：命令行 + SSH（推荐）
--------------------------------------------------------
首次克隆：
    git clone git@github.com:你的用户名/仓库名.git
    # SSH 方式克隆，自动配置 origin 和上游关联

    cd 仓库名
    # 进入仓库目录

日常标准流程：
    git status
    # 看当前分支和文件状态

    git branch
    # 确认当前分支是 main 还是 master

    git remote -v
    # 确认远程地址正确

    git pull --rebase origin main
    # 先拉远程最新提交，再把本地提交接到后面
    # 本地是 master 就写 git pull --rebase origin master

    git add .
    # 添加修改

    git commit -m "描述这次修改"
    # 提交到本地

    git push origin main
    # 推送到远程
    # 已建立上游关联时可直接 git push

如果 push 被拒绝：
    git pull --rebase origin main
    # 远程有本地没有的提交，先同步
    # 有冲突则解决后：
    git add 冲突文件
    git rebase --continue
    git push origin main

如果本地有未提交修改，pull 报会被覆盖：
    git stash
    # 临时收起未提交修改

    git pull --rebase origin main
    # 拉取远程

    git stash pop
    # 恢复临时修改

分支名不一致（本地 master、远程 main）：
    git branch -M main
    # 本地 master 改名 main

    git push -u origin main
    # 推 main 并建立关联


========================================================
文件夹四：常见的问题（1~6）
========================================================

问题 1：fatal: not a git repository
--------------------------------------------------------
现象：
    git add .
    # 报 fatal: not a git repository (or any of the parent directories): .git

原因：
  当前目录及所有父目录都没有 .git 文件夹。

解决：
    cd 项目根目录
    # 进入项目根目录

    git init
    # 初始化仓库

  或找到已有 .git 的那一层再执行命令。

问题 2：fatal: No configured push destination
--------------------------------------------------------
现象：
    git push
    # 报 fatal: No configured push destination.

原因：
  仓库存在，但没有配置远程地址。

解决：
    git remote -v
    # 输出为空说明没配

    git remote add origin git@github.com:你的用户名/仓库名.git
    # 添加远程地址

    git remote -v
    # 确认有 origin 的 fetch 和 push 两行

    git push -u origin main
    # 第一次推送并建立关联
    # 本地是 master 就写 git push -u origin master

问题 3：error: src refspec main does not match any
--------------------------------------------------------
现象：
    git push origin main
    # 报 error: src refspec main does not match any

原因：
  本地没有 main 分支。可能分支叫 master，也可能还没 commit。

解决：
    git branch
    # 看当前分支名

    git log --oneline -5
    # 看有没有提交

  本地是 master：
    git push -u origin master

  想统一成 main：
    git branch -M main
    git push -u origin main

问题 4：git push -u main 参数顺序错误
--------------------------------------------------------
现象：
    git push -u main
    # 报 The current branch master has no upstream branch.
    # 并提示 git push --set-upstream main master

原因：
  git push 参数顺序是 git push -u <远程名> <分支名>。
  只写 main，Git 把 main 当成远程名。

正确写法：
    git push -u origin master
    # origin 是远程名，master 是分支名

  或：
    git branch -M main
    git push -u origin main

问题 5：nothing to commit, working tree clean
--------------------------------------------------------
现象：
    git add .
    git commit -m "增加代码"
    # 报 nothing to commit, working tree clean

原因：
  工作区没有未提交修改。可能之前已 commit，或文件被 .gitignore 忽略。

解决：
    git log --oneline -5
    # 看有没有提交记录

    git remote -v
    # 看远程有没有配

  有提交、有远程：
    git push -u origin master
    # 直接推已有提交，不需要再 commit

  关键：nothing to commit 不代表没东西可推。

问题 6：push 被拒绝 fetch first / non-fast-forward
--------------------------------------------------------
现象：
    git push -u origin main
    # 报 ! [rejected] main -> main (fetch first)
    # 或 non-fast-forward

原因：
  远程有本地没有的提交，常见于创建仓库时勾了 README 或网页上改过文件。

解决：
    git pull origin main --rebase
    # 拉远程最新提交，并把本地提交接到后面
    # 本地是 master 就写 git pull origin master --rebase

  如有冲突：
    git status
    # 查看冲突文件

    打开冲突文件，搜索 <<<<<<<、=======、>>>>>>>
    手动修改成想要的内容，保存

    git add 冲突文件
    # 标记冲突已解决

    git rebase --continue
    # 继续 rebase

    git push -u origin main
    # 再次推送

  不要轻易用 git push -f，会覆盖远程提交。


========================================================
总结：最常用命令速查
========================================================
查看状态：
    git status
    git branch
    git remote -v

首次上传（SSH + main）：
    git init
    git add .
    git commit -m "first commit"
    git branch -M main
    git remote add origin git@github.com:你的用户名/仓库名.git
    git remote -v
    git push -u origin main

日常更新：
    git pull --rebase origin main
    git add .
    git commit -m "说明"
    git push

新分支：
    git switch -c 你的分支名
    git add .
    git commit -m "说明"
    git push -u origin 你的分支名

分支名是 master 时，把上面命令里的 main 换成 master。
