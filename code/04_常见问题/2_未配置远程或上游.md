# 问题 2：没有推送目标或上游

本次真实配置：仓库 Patick274/wheeltec_robot，origin 为本地远程别名，main 为目标分支。
只有首次 push 成功后才能据此确认上游建立；成功 clone 的默认分支通常已有上游。
Linux SSH 和已有 origin 修改地址的步骤见 [A/B 简明流程](../03_另一台电脑拉取与上传/GitHub_AB两机同步简明流程.md)。

No configured push destination 表示没有可用的推送目标；no upstream branch 常表示当前分支没有上游。
```powershell
git remote -v
git branch -vv
git branch --show-current
# 分别检查远程地址、分支上游、当前分支名。
```
没有 origin 时，本次 Windows 仓库使用：
```powershell
git remote add origin https://github.com/Patick274/wheeltec_robot.git
git push -u origin main
# 当前分支确实为 main 且有提交时执行；其他分支用自己的名称。
```
已有 origin 地址写错时：git remote set-url origin 正确URL。
已有 origin、只是当前分支没上游：git push -u origin 当前分支名。
认证失败或没有写权限是另外的问题，检查登录账号、仓库权限及组织规则。
