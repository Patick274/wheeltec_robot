## 4. 当前实现与用户要求

### 4.1 必须保持的用户要求

- 方向键上升/下降；正速度上升，负速度下降，不改方向参数来迁就软件。
- 中段1000 rpm，本方向末端约100 mm为100 rpm。
- 底盘运动过程中，升降实际速度不得超过100 rpm。
- 新增顶端总高度指令：目标总高度 = 初始总高度 + 伸长量，单位米。
- 初始总高度由用户后续实测，未知时不填假值。
- Windows/Jetson代码统一LF，不引入CRLF。
- 不擅自修改电机匹配、限位映射、极性和已确认的机械标定。

### 4.2 实物门禁与模式

实物config/lift.yaml当前四项均false：

- motion_enabled
- commissioning_confirmed
- drive_limits_verified
- keyboard_control_enabled

其他重要配置：

- initial_top_height_m=null。
- require_base_feedback=true，allow_lift_while_base_moving=true。
- 累计运动预算110秒，连续静止冷却1080秒。
- 图纸工作制2分钟运行/18分钟停止；预算不跨进程持久化，重启不证明冷却完成。
- 约4190 mm全行程按现配速可能约136秒，不能直接连续跑整段/往返。
- 键盘后端心跳超时0.4秒，终端松键模拟超时0.25秒；非安全认证保持运行按钮。

模式由ROS显式使能时写入驱动器RAM：

| 场景 | ROS入口 | 6060模式 |
|---|---|---:|
| 键盘控制 | /lift/enable_keyboard | 3，带加减速的速度模式 |
| 位置/顶端高度 | /lift/enable | 1，位置模式 |

ROS读取6061确认模式采用；不需要每次用KincoServoPro手动改模式或写EEPROM。
切模式须先停稳并在机械保持可靠的条件下取消使能，再显式启用另一模式。
高度请求不会自动使能或自动从键盘模式切到位置模式。

### 4.3 已修复的前三项问题

1. 底盘最终串口入口不再直接转发非零速度：
   - 20Hz发送/lift/base_motion_request，UInt64本轮请求序号。
   - 升降确认实际转速和目标转速均不超过100 rpm、反馈健康后，在/lift/base_motion_permit回送同序号。
   - 底盘只接受本轮序号；许可或速度指令0.3秒过期、底盘反馈0.5秒过期则发送零速。
   - 实测零速连续1秒后才释放请求；请求失联撤销许可，但保留升降100 rpm限制。
   - 独立安全回调队列，不等待串口读循环；没有健康lift节点时底盘不能行驶。
   - 该软件机制不能代替下位机失联看门狗、物理急停和机械保持。
2. 键盘空格/Esc/q/退出停车覆盖位置任务：
   - 速度模式写60FF=0。
   - 位置模式605D=2，6040=0x012F设置bit8暂停，保留使能。
   - 取消本地旧目标；busy等真实速度停稳才清除，2秒未停稳进入故障停车。
   - 新目标先在暂停保持期间装入，最后3F解除暂停，不恢复旧任务。
   - 全局/lift/stop及严重异常仍可能撤掉保持力，不等于普通暂停。
3. 位置/点动与键盘共用坐标核验：
   - 真实下限位有效、上限位无效、静止、6410:03精度匹配。
   - 固定速度区下，原始下端计数须匹配配置参考约±1 mm。
   - 未确认不能用jog绕过；计数跳变/精度改变会撤销参考。
   - 不清编码器、不自动平移旧速度区、不把首次反馈当机械零点。

### C. 隔离ROS仿真

#### C0. master端口警告处理

当前错误背景：启动roscore -p 11321的终端仍保留ROS_MASTER_URI指向11311。

在每个Jetson测试终端，进入已构建工作区后，先source，再设置本终端环境：

```bash
source devel/setup.bash
unset ROS_IP
export ROS_HOSTNAME=127.0.0.1
export ROS_MASTER_URI=http://127.0.0.1:11321
echo "$ROS_MASTER_URI"
```

这些export不影响其他终端，必须逐个设置；也不要写入.bashrc覆盖日常机器人配置。
如需退出，只关闭刚启动的测试节点/master，不关闭不属于本次测试的真实机器人主节点。

终端一：

```bash
roscore -p 11321
```

终端二：

```bash
roslaunch kinco_lift_control lift.launch simulate:=true
```

终端三：

```bash
rosparam get /lift/simulate
rosnode list
rostopic echo -n 1 /lift/status
```

初步通过标准：

- /lift/simulate=true。
- 日志出现SIMULATION: no physical CAN access.
- 状态connected=true、enabled=false，位置约147599、lower_limit=true。
- master上没有真实底盘/导航/真实CAN控制节点。
- 四项门禁在仿真overlay中为true是正常的，但实物配置文件必须保持false。

关键危险：simulate=true虽不打开CAN，但仍能发布“模拟低速许可”。绝不能让真实底盘串口节点使用这些许可。
隔离验证期间不要启动wheeltec_robot_node来“顺便看看底盘动不动”。

#### C1. 按用例验证，不一次性下发整套运动

所有使能、命令发布和服务调用仅对已确认的内存仿真节点执行；simulate不是true就停止。

| 用例 | 操作要点 | 通过标准 |
|---|---|---|
| C01 启动门禁 | 只启动仿真并观察 | 不自动使能/移动/回原 |
| C02 会话确认 | 静止下限位调用confirm_keyboard_coordinates或键盘c | 参考有效，原始计数不被清零 |
| C03 键盘使能 | Linux有焦点TTY运行lift_keyboard.py，再显式e | 模式3、使能，但未按方向键时不移动 |
| C04 正反向 | 短按/长按上升，松键停稳，再下降 | 正速度升、负速度降；换向先停稳 |
| C05 松键/失联 | 松键、退出键盘、停止方向心跳 | 速度目标归零，不自动续跑；记录实际延迟 |
| C06 普通停车 | 空格/Esc/q、键盘退出 | 不同模式均停车，旧目标不恢复 |
| C07 分区 | 在模拟器/单测中覆盖阈值两侧与等值 | 正确方向进入100 rpm，退出相反端不误限速 |
| C08 端点 | 模拟接近正常端点/硬限位 | 禁止继续向外，允许反向退出；双限位异常拒绝 |
| C09 高度参数缺失 | initial_top_height_m=null | 高度服务明确拒绝，不暗用0 |
| C10 米制目标 | 单独仿真配置设假定H0=0.8 m，目标1.1 m | 目标伸长300 mm，不是再升1.1 m |
| C11 位置任务暂停 | 模式1执行目标，键盘普通停车 | bit8暂停、保留使能；busy等反馈停稳清除 |
| C12 暂停后新目标 | 旧任务已取消，再显式给新目标 | 新目标先装载，再解除暂停，不恢复旧行程 |
| C13 模式互斥 | 模式3直接请求位置任务等 | 拒绝越模式请求，不偷偷使能/切模式 |
| C14 坐标核验 | 模拟错误下端、精度改变、计数突变 | 拒绝运动/撤销参考，不平移阈值掩盖问题 |
| C15 工作制 | 仅在无硬件单测注入时间 | 短暂停顿/复位不清预算，完整冷却才恢复 |

补充：

- 可通过rosrun kinco_lift_control lift_keyboard.py启动键盘入口；不要用roslaunch启动依赖TTY的键盘脚本。
- 普通终端没有可靠key-up，首次按键重复延迟可能造成先停一下，不能通过加大超时掩盖。
- H0仿真假值必须放独立测试配置，启动时加载且保持simulate=true，不能写入实物配置。
- LiftConfig是启动时参数快照；仅rosparam set后不能假定控制器已动态采用H0等新参数。
- 可重启纯内存模拟器恢复测试初始位置；不能将此习惯用于真机原点/冷却处理。

#### C2. 底盘低速许可的软件联动

仅使用单测、虚拟底盘节点或假串口/PTY；不得打开真实底盘串口。

- [ ] 升降模拟1000 rpm，底盘请求运动；底盘先保持零速。
- [ ] 目标上限已100但实际仍大于100时，许可仍拒绝。
- [ ] 目标与实际均不超过100、反馈健康，才回送本轮序号。
- [ ] 请求保持期间发起新的升降任务，仍不能超过100。
- [ ] 许可过期、请求失联、升降节点退出/故障、底盘指令/反馈过期，输出零速。
- [ ] 旧轮次或旧进程许可不能放行新一轮运动。
- [ ] 极小非零线速度/角速度同样先申请许可。
- [ ] 底盘命令零但实际仍运动时，不能释放升降限速。
- [ ] 连续实测零速1秒后才释放，短暂停顿不触发升降突增速。
- [ ] 证明仿真ROS许可没有桥接到真实机器人。

通过标准：保存目标速度、实际速度、请求序号、回送序号、底盘最终输出与时间戳；不能只看一个Bool。
/lift/base_motion_permitted是显示/辅助接口；当前C++实际联锁使用UInt64请求/回送序号。

### E. 驱动器只读SDO与ROS反馈

前置条件：D通过；实物升降停稳、支撑可靠、无其他控制主站。
关闭KS3通信及其他CAN控制程序。不要同时运行probe和真实lift节点。

独立只读探测（接口/站号已确认后）：

```bash
python3 scripts/probe_drive.py --interface can0 --node-id 1
```

性质说明：probe会发送只读SDO请求，不是完全不发报文；不会写控制字、使能或设原点。
diagnose_can则不打开CAN套接字、不发送CAN帧，二者不能混淆。

读取与验收：

- [ ] 确认是目标FD125，站号不是盲猜或对整条总线扫描。
- [ ] 6041状态、6063实际位置、606C速度、60FD限位、2601错误、6060设定模式可稳定读取。
- [ ] 如需扩展只读核验，另读2602错误2、6061有效模式、6410:03精度等，不擅自写对象。
- [ ] 读取超时/SDO中止后锁住会话，不自动重发运动或恢复使能。
- [ ] 对照当前物理上下位置检查限位反馈，不把历史状态当现在的限位。
- [ ] 确认当前计数仍适用于既有速度区；不匹配就停在核验，不用清零解决。

退出probe后，可在物理配置四项仍为false、确认simulate=false的条件下启动真实只读lift节点。
只读阶段不调用enable/enable_keyboard/reset_fault/reference或任何运动服务。
通过标准：稳定只读通信、位置/输入/错误与实物一致，没有因启动节点产生运动或参数写入。

### G. 受限实机验证：计划，不是当前可执行步骤

只有A-F对应前置项通过，且用户明确授权真实运动，才由现场人员配合执行。

先建立：

- [ ] 可靠的机械保持/防坠/支撑与安全活动空间；不依赖“伺服使能等于机械制动”。
- [ ] 现场人员能独立操作物理急停，不用键盘/网络作为唯一停机方式。
- [ ] 制定解除机械支撑与恢复支撑的方法，不带着会阻挡行程的支撑强行驱动。
- [ ] 确认负载、姿态、供电与驱动器报警策略。
- [ ] 问题处置和回退路径明确，计数框架与当次参考已核对。
- [ ] 退出仿真，证明真实ROS主机未连接任何模拟许可源。

验证顺序建议：

1. 底盘可靠静止，先最低可控速度、最小有限位移确认方向与普通停车。
2. 验证键盘松键、退出、心跳丢失与位置暂停；普通停车保持与异常停车分别记录。
3. 在可控余量内验证上下方向限位及反向退出，不以高速撞限位方式验收。
4. 逐级验证低速区、正常端点内缩和制动距离，记录速度、触发与停稳位置；不直接整段1000 rpm。
5. 校准初始总高度和伸长换算，用小距离总高度目标验证，不超工作制。
6. 在现场受控方案下验证CAN/进程失联行为；禁止带悬空负载随意拔线或断电来“测试安全”。
7. 最后才验证底盘先等待升降低速、再起步及许可丢失停车，逐步扩展速度/行程；高位行车单独验收。

实际速度换算（当前65536 inc/转配置）：

rpm = 606C原始值 * 1875 / (512 * 65536)

不要把606C原始数值直接当rpm；参数/精度不一致时此公式不能照用。
任何反向、突跳、异常声响、下滑、限位错误、速度超限、通信异常都应停止推进，现场先确保人和设备安全。
不要自动复位后继续未完成目标。
