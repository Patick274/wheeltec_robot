## 问题与采用的方案

### 1. 上限位受困：已增加正式受监督释放流程

原问题：参考失效后，上限位有效，回下限位恢复与从帧建参考都拒绝；键盘未确认也不能下行。现场曾使用节点外直接CAN脚本释放，缺少正式节点的联锁与通信监督。

本次新增 **/lift/escape_upper_limit（std_srvs/Trigger）**，对应控制器 escape_upper_limit：

- 只接受未使能、空闲、无故障锁存、只有上限位有效的状态。
- 门禁、预算、静止底盘反馈、编码器精度、当前原始帧位置必须有效。
- 默认50rpm向下，最多10s或20mm。首次非零速度指令前再次核验握手期间可能变化的反馈和底盘状态。
- 复用正式使能握手与节点保护；周期检查故障、模式、精度、帧跳变、预算、反向/超速、双限位、开关释放后重触及底盘反馈。
- 必须“上限位释放且进入正常范围”后才请求零速度，再由反馈确认停稳。
- 成功后保持使能与节点保护，避免自动撤使能引起现场已观察到的上漂；不自动建零、不清编码器、不恢复旧任务。
- holding状态继续检查速度和累计位置漂移，绕开需要键盘确认的普通速度分支。
- 逃离及保持期间不给底盘运动许可；明确disable或stop后退出该状态。

释放目标由当前配置计算：
min(zones.upper_stop, zones.lower + travel_mm换算计数)。
因此保留 travel_mm=4190 的正常运动约束；没有把正常行程扩大到物理开关外，也没有屏蔽限位。

新增状态：

- upper_escape_phase：空、starting、descending、halting、holding。
- upper_escape_target_counts：进入正常范围所需的原始计数目标。
- upper_escape_complete：只有holding、上限位已释放且已进入目标范围时为true。
- busy在反馈停稳前保持true；服务成功回执仅表示启动。

提前按暂停或键盘中立会取消下降，可能进入holding但complete=false，不能误认为已完成释放。

### 2. 高位撤使能上漂：采用保持使能的收尾

日志记录高位撤使能后上漂约0.74mm。新流程正常完成后不自动撤使能。
保持使能不是独立机械防坠：断电、通信失效或故障停止的保持能力仍取决于驱动器策略与机械条件。

日志“唯一安全停泊态=下限位”可作为当前现场操作经验，尚不足以证明所有负载、供电和失效场景下的机械安全性。长期高位停泊方案仍需独立确认。

### 3. 暂停后恢复自动续动：已修复

此前普通暂停或键盘中立只清一次60FF，但 recovering 仍在；下一轮恢复会重发下行速度。

现在：

- 回下限位期间的普通暂停/中立会取消恢复、请求停止并锁存，不再重发速度。
- 上端释放期间暂停/中立进入受监督停车与保持，不会恢复下降。
- 恢复/释放期间拒绝非零键盘指令，防止两条控制路径竞争。
- 全局stop随时可以取消释放和保持状态。

### 4. LiftReject 分级：保留，并修复一处参考清除

纯参数/状态拒绝继续只返回原因，不自动故障锁存；真实通信、驱动器、模式与帧异常仍按故障处理。

修复 _record_checked_reference：现在先核验限位与静止条件，纯拒绝不会先清掉已有参考。精度或原始帧不符仍属于真实完整性错误，不降级为普通拒绝。

- 测试保留物理限位位于软件行程外的情况，并额外模拟开关释放迟滞与卡住。
- 修复进程级测试的中文路径编码、Windows临时文件重开、socket关闭与子进程清理问题。

## 现场工具与接口兼容变化

日志还记录rosservice冷代理约1.9s延迟。位置触发的停车判断应在控制节点内部依据新反馈完成,不能把外部命令行服务当实时制动触发器。新释放流程由poll内部判断位置和停稳;现场制动距离继续使用带时间戳的连续采样,不能用服务回执时间代替动作时间。

**scripts/limit_escape.py 已从直接操作CAN改为正式ROS服务客户端。旧操作方式要求停lift节点，新版本要求lift节点运行。**
它不再硬编码速度/驱动器、不绕过门禁、不自行复位或撤使能。

现场人员完成许可、确认门禁配置与真实底盘静止反馈后，可选择一个入口：

```bash
rosservice call /lift/escape_upper_limit "{}"
# 或
python3 scripts/field_p2.py escape_upper
# 兼容入口:
python3 scripts/limit_escape.py
```

这些命令仅写入本交接说明，本次没有执行。门禁保持false时请求会被拒绝。

正式现场验收应检查：

1. 回执后依次看到descending、halting、holding，最终upper_escape_complete=true；取消或失败不能当成功。
2. 上限位已释放、实际速度接近0、busy=false，且保持使能；位置未自动归零。
3. 经现场确认后显式disable，再调用reference_from_frame、显式启用位置模式，分段回低位；到真实下限位后用reference_here重新物理对零。新流程不自动串联这些操作。
4. 若失败锁存，先检查故障和现场状态；不自动复位并重复执行。

这里只验证最小上端释放，不从顶部直接执行约4m的单次回家；常规任务仍受速度区、超时、预算和行程限制。
